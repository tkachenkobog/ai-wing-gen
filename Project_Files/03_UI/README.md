# Wing Generator UI

Графічна оболонка для `01_PYTHON/NX-2_DE_Optimization.py`. Робить три речі:

1. **Редагує параметри**, які раніше були захардкоджені у скрипті. На екрані —
   10 значень, що справді змінюють літак; решта 90 внутрішніх коефіцієнтів
   доступні за перемикачем, але вже заповнені значеннями зі скрипта.
2. **Запускає** оптимізатор і показує лог у реальному часі.
3. **Показує результати** — таблицю метрик, сім графіків на canvas, збіжність, STL.

## Запуск

```
cd 03_UI
npm install        # один раз
npm start
```

## Проєкти та дослідження

**Дослідження** — це один прогін зі своїми вхідними даними. Проєкт — набір
досліджень одного літака.

```
05_STUDIES/
  index.json                       останнє відкрите дослідження
  nosytel-3-kh/
    project.json
    2026-07-27_ar-8-katapulta/
      study.json                   метадані та зведення
      requirements.json            знімок вимог
      wing_config.json             знімок параметрів (RESULTS_ROOT веде сюди ж)
      sizing_report.json
      RESULTS/                     eval_*, best_so_far.json
      run.log
```

Як тільки в дослідженні з'явилась перша оцінка, воно **заморожується**: вимоги й
параметри стають лише для читання, «Підібрати розмір» і «Запустити» блокуються.
Так гарантується, що показані числа відповідають наявним результатам. Щоб
рахувати інакше — **клонуйте** дослідження: вхідні дані успадкуються, результати
почнуться з нуля. Заморозку можна зняти, очистивши результати.

Заморожування визначається наявністю тек `eval_*`, а не прапорцем у файлі, тож
метадані не можуть розійтися з тим, що на диску.

`04_SIZING/requirements.json` і `01_PYTHON/wing_config.json` — це **шаблони**, з
яких народжується нове дослідження. Прогони їх не змінюють, і запуск скриптів
із командного рядка без досліджень працює як раніше.

Перенести старі результати у перше дослідження:

```
py -3 05_STUDIES/migrate_legacy.py --dry-run
py -3 05_STUDIES/migrate_legacy.py
```

Потрібен Python із `aerosandbox`, `scipy`, `numpy`, `matplotlib`. Застосунок сам
шукає інтерпретатор у порядку `py -3` → `python` → `python3` і показує знайдену
версію в правому верхньому куті.

Графіки малює сам UI із `curves.json` кожної оцінки — рендер PNG матплотлібом
із проєкту прибраний зовсім (він коштував 273 мс і 195 КБ на варіант проти
0.5 мс і 2.5 КБ). `matplotlib` лишився в залежностях лише через `Path`, яким
STL-експорт закриває законцівки. `pyvista` більше не потрібен.

## Як це під'єднано до скрипта

Оригінальний скрипт **не переписувався**. До нього додано один блок
`_apply_external_config()` (шукайте коментар `EXTERNAL CONFIG OVERRIDE`), який:

* читає `01_PYTHON/wing_config.json` (або шлях зі змінної оточення `WING_CONFIG`);
* накладає значення на константи, визначені вище в файлі;
* **перераховує похідні величини** — `Y_TIP`, `AR_FIXED`, `G_MODULUS`, `DE_BOUNDS`
  і шляхи всередині `RESULTS_ROOT`;
* якщо файлу немає — нічого не робить, і скрипт поводиться точно як раніше.

Оригінал лежить поруч: `01_PYTHON/NX-2_DE_Optimization.ORIGINAL.py`.
Щоб повністю відкотитися — видаліть `wing_config.json` або скопіюйте оригінал назад.

Скрипт так само запускається й без UI:

```
cd 01_PYTHON
py -3 NX-2_DE_Optimization.py
```

## Файли

| Файл | Призначення |
|---|---|
| `main.js` | процес Electron: пошук Python, запуск/зупинка розрахунку, читання результатів |
| `preload.js` | містк між процесами (`contextIsolation`, без `nodeIntegration`) |
| `renderer/` | сам інтерфейс — без зовнішніх залежностей, усе локально |
| `param_schema.json` | **генерується** — опис форми (групи, підписи, одиниці, дефолти) |
| `tools/gen_schema.py` | генератор схеми: імпортує скрипт і зчитує з нього актуальні дефолти |

Якщо додасте у скрипт нову константу і захочете її в UI — впишіть її в таблицю
`PARAMS` у `tools/gen_schema.py` і виконайте:

```
npm run schema
```

Дефолти в схемі беруться **зі самого скрипта**, тому вони не можуть розійтися
з кодом.

## Вкладка «Параметри»

За замовчуванням показано лише базовий набір:

| | Параметри |
|---|---|
| Точка проєктування | `S_FIXED`, `B_FULL`, `V_DESIGN`, `CL_TARGET`, `AIRFOIL_NAME` |
| Керування прогоном | `popsize`, `maxiter`, `workers`, `time_budget_hours` |
| Вивід | `RESULTS_ROOT` |

Решта (габаритні обмеження, ваги цільової функції, штрафи, сітка, структура,
межі 16 змінних проєктування) з'являється за чекбоксом **«Решта параметрів»**.
Заповнювати її не потрібно — вона згенерована з самого скрипта і працює як є.

Пошук працює по всьому набору незалежно від перемикача — введіть `S_FIXED` або
частину підпису. Змінені відносно дефолту поля підсвічуються жовтим, кнопка `↺`
повертає одне поле до дефолту.

Панель **«Точка проєктування»** рахує в реальному часі те, чого у скрипті немає:
підйомну силу `0.5·ρ·V²·S·CL` і повну масу, яку крило здатне нести. Введіть
потрібне корисне навантаження — і побачите, яку частку від злітної маси воно
складе. Якщо понад 100% — точка проєктування фізично не тримає такий літак.

> Зміни застосуються тільки після **«Зберегти конфіг»**. Кнопка «Запустити»
> зберігає автоматично.

## Вкладка «Розрахунок»

Живий лог, кількість оцінок відносно стелі, найкраща цільова функція та L/D.
«Стоп» вбиває все дерево процесів (важливо при `workers = -1`).

## Вкладка «Результати»

Список оцінок із сортуванням за цільовою функцією, L/D або номером. Теги
показують, які обмеження порушено:

| Тег | Що це |
|---|---|
| `MIDCHORD` | хорда в контрольній станції менша за `C_MID_MIN` |
| `XMAX` | габарит по X перевищує `X_MAX_LIMIT` |
| `CMIN` | десь на крилі хорда менша за `C_GLOBAL_MIN` |
| `THIN` | м'який штраф за тонку хорду |
| `MONO` | хорда десь зростає до законцівки |
| `TIPTAPER` | «плато» хорди біля законцівки |
| `TIPTW` | крутка законцівки більша за дозволену |
| `CLBIN` | CL від VLM не збігається з проінтегрованим по розподілу |
| `CGCLAMP` | центрівка вперлася в межу `XCG_MIN`/`XCG_MAX` |
| `STAB` | порушено обмеження `Cn_beta` / `Cl_beta` |

Графік збіжності: сині точки — окремі оцінки, зелена лінія — найкраще на цей
момент. Червоні точки — значення, зрізані за верхньою межею шкали (зазвичай це
штрафи за порушені жорсткі обмеження, вони на 5–7 порядків більші за нормальні).

## Що UI НЕ робить

Він не змінює фізику. Зокрема залишаються чинними два обмеження самого скрипта:

* **Немає моделі мас.** Злітна маса, маса конструкції та корисне навантаження
  у розрахунок не входять. Панель «Точка проєктування» — це довідкова
  прикидка збоку, а не частина оптимізації.
* **Структурний блок — проксі.** `EI_ROOT_BASE` постулюється константою, а не
  рахується з перерізу; лонжеронів у моделі немає взагалі. Група параметрів
  «Структура» підсвічена жовтим саме тому — ці числа придатні лише для
  порівняння варіантів між собою.

## Відоме

Початкова геометрія (оригінальний NX-2, перемасштабований) має хорду законцівки
**0.0389 м** при `C_GLOBAL_MIN = 0.04`. Тобто стартова точка одразу порушує
жорстке обмеження, і цільова функція на першій оцінці ≈ **159 000** замість
очікуваних ≈ −17. DE спершу мусить вийти з цього штрафу.

Якщо це не задумано — поставте `C_GLOBAL_MIN = 0.035`, і стартова точка стане
допустимою.
